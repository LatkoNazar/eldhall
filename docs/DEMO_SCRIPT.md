## Відео (≈2:30, окремі вікна /chat і /operator)

Готового split-screen маршруту немає. Підготуй окрему локальну demo-базу, API та worker: `SUPPORT_STORE=postgres`, `SUPPORT_EXECUTION=worker`, `DEMO_RESET_ENABLED=true`. Runtime: DSH, `LLM_PROVIDER=google`, `LLM_MODEL=gemini-3.5-flash-lite` і приватний серверний ключ. Offline rules-режим має бути явно позначений.

Авторизований `POST /api/v1/demo/reset` виконуй лише у цій demo-базі; production за замовчуванням не відкриває personas/reset. Відкрий `/chat` і `/operator`, увійди операторським токеном, не показуючи його. Не записуй `.env` або session credentials. Час орієнтовний: API приймає повідомлення з 202, UI показує queued/running і чекає фактичного завершення worker run.

## Слайди (≤10)
1. **Проблема** — повторювані грошові звернення, злі клієнти чекають, ручна робота в білінгу.
2. **Чому чат-боти не рятують** — відповідають, але не діють; або діють без контролю.
3. **Продукт** — copilot: intent + sentiment → дані + policy → дія → approval → виконання → аудит. Для різних бізнесів.
4. **AI reasoning & context** — controlled context, tool call `lookup_payments`, типізоване рішення, fallback.
5. **Реальна дія** — refund змінює стан у БД (провайдер симульований — кажемо прямо).
6. **Безпека** — LLM не пише в БД; policy engine; human approval прив'язаний до argsHash; atomic claim + UNIQUE; honest failures; sentiment ≠ авторизація.
7. **Перевірки** — лише виміряні результати зі STATUS. Не використовувати запланований eval, вигадані accuracy чи економію кліків як готовий результат.
8. **Архітектура** — діаграма з [ARCHITECTURE](ARCHITECTURE.md): Fastify API + worker, PostgreSQL, Redis/BullMQ, native DSH та optional React. JSON/KB/prose-skills/read-only MCP; пошук лексичний. Oracle/cloud і container startup не підтверджені.
9. **Live demo** — вбудоване відео.
10. **Межі й потенціал** — ліцензію ще не обрано, managed cloud не розгорнуто; roadmap: реальні провайдери, SSO/RBAC, канали. Поточна автентифікація — один staff bearer та opaque customer session.

## Здача
`git archive HEAD` включає лише committed-файли й не містить незакомічену реалізацію. Перед створенням пакета звір перевірений checkout і склад архіву; не додавай `.env`, node_modules чи приватні `.omc`-артефакти. Не стверджуй, що ZIP, слайди або відео готові, доки їх не створено й не перевірено. Цей сценарій не дозволяє автоматичний commit, push чи deploy.

Якщо показуєш повторний API-запит, перевіряй саме **execute** з тим самим `argsHash`: конфлікт і жодного нового refund. Повторне approve не доводить ідемпотентність виконання.
