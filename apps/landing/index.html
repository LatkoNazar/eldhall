How Eldhall differs from a chatbot

A typical chatbot

  • Replies with a template and sends you to a form
  • Cannot see payments or company rules
  • Either does nothing or acts without oversight

Eldhall Copilot

  • Finds customer data through permitted tools
  • Checks business rules before every action
  • Proposes an action; a person approves; the server executes

How it works

Five clear steps from request to resolution.

  1. 01

    Request

    The customer writes in chat. The session identifies them, not the message text.

  2. 02

    AI analysis

    Intent, mood and urgency. AI calls a permitted tool to find payments.

  3. 03

    Rule check

    The policy engine checks ownership, duplicates, limits and payment status.

  4. 04

    Action or approval

    Safe actions run immediately; risky actions in this flow wait for an operator.

  5. 05

    Resolution

    The server updates the state, informs the customer and records every step.

Features

Everything support needs to act quickly and safely.

Context-aware AI

The server gathers the profile, recent payments, business policy and conversation history.

Action execution

Actions use an explicit tool registry with typed arguments. No arbitrary database access.

Sentiment detection

Frustration, rudeness and urgency affect priority, tone and escalation, never financial permission.

Human oversight

The operator reviews the analysis, signals and checks, then approves the exact proposed action.

Policy guardrails

Each business has its own limits, duplicate window and permitted tools.

Case tracking and audit

Cases, proposals, operator decisions, model runs and action results are recorded.

    Safety by default

    AI proposes. Rules check. People decide.

    In this refund flow, the model has no direct database or payment-provider access.

    • Approval is bound to the operation

      The operator approves a specific payment and amount. Changed arguments invalidate that approval.

    • No repeat execution

      A second click creates no second refund: approval is single-use and each payment can be refunded only once.

    • Honest outcomes

      If the provider has not confirmed the action, the customer hears that, not an invented success.

    • Identity comes from the session

      A payment number in a message does not grant access to someone else’s data.
