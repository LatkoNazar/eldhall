## Verify the existing archive (no capture or render)

From the repository root:

```sh
node demos/mvp/pitch/scripts/verify.mjs --source-only
node --test demos/mvp/pitch/scripts/verify.test.mjs
# Only this subtree from the existing private remote; no unrelated reference footage:
git lfs pull --include="demos/mvp/pitch/**" --exclude=""
cd demos/mvp/pitch
npm run verify
npm run build
```

`--source-only` uses Node built-ins and accepts exact LFS pointers bound to `archive-assets.json`. It checks JSON, unique scenes, captions, generated timing, footage ledger, fonts, render output contract, and the hashes of the dated deck/text originals. It does not run ffprobe, install dependencies or fetch anything. The tests create a temporary pointer-only checkout to exercise this path.

Default `verify` requires all 16 materialized asset bytes to match the archival receipt, validates WOFF2 signatures, and uses installed `ffprobe` (or explicit `FFPROBE_PATH`) to check media dimensions, minimum duration and the archived export's 30 fps. It is metadata/integrity validation, not a new visual review or full decode. Default `build` runs full verification and regenerates HTML/timing/ledger/subtitles with `--final`; it cannot silently accept missing footage or LFS pointers. It needs no npm dependencies for these two steps, only Node and ffprobe. `npm ci` is needed before Hyperframes preview/check/render.

The archived export remains untouched. A deliberately requested future `npm run render` writes **`exports/eldhall-pitch-uk.mp4` at 30 fps**. That fresh output is separate from the preserved archive; this cleanup does not render it. Capturing changed scenes requires a new reviewed receipt/evidence rather than reusing the immutable 2026-10-31 hashes.

## Historical capture recipe (destructive; disposable demo only)

**Do not run this against restored development history or production.** It calls `/api/v1/demo/reset` and writes new recordings. Use a separately authorized disposable demo backend; an existing backend that disables reset is unsuitable. The recipe documents the original process and was not executed for this cleanup.
1. Start the MVP (API + frontend) and check the URL in `capture.config.json` (`appUrl`, `apiUrl`). The `/chat` and `/operator` pages must exist.
2. Check the locators in `capture.config.json` against the real UI (button names, labels).
3. Record and verify:
   ```bash
   OPERATOR_TOKEN=<token> node scripts/capture.mjs
   ```
   The script does a demo reset and two continuous sessions (chat + console): Olena → copilot reply → Inbox P1 case + signals → policy checklist → **«Погодити повернення»** (approved, no money moved) → separate **«Виконати погоджену дію»** (executed, `SIM-RF-…`) → confirmation in chat; Ivan (via the real chat API) → `within_refund_limit` denial + escalation. Then it checks through the API: Olena `resolved` + 1 refund + `executed`; Ivan `escalated` + `denied` + 0 refunds. If the state does not match, no slot is written (`capture/evidence.json`). In rules mode it warns that the captions must not claim LLM tool calls.
4. `node scripts/build.mjs --final` → `npx hyperframes check` → snapshot review:
   ```bash
   npx hyperframes snapshot --at 6,12,18,24,30,36 --no-end --output .hyperframes/review
   ```
5. Final render (~3–5 min at `delivery` quality):
   ```bash
   npx hyperframes render --fps 30 --quality delivery --workers 3 --output exports/eldhall-pitch-uk.mp4
   ```
6. QA for any separately requested new render: `ffprobe` (1920×1080, 30 fps, ~44 s), a full decode `ffmpeg -v error -i exports/eldhall-pitch-uk.mp4 -f null -`, one full watch-through, and a check that every caption matches `capture/evidence.json`.
7. Original archived decks already contain video. Do not overwrite them with a new render; prepare a separately reviewed presentation if requested.

## Known limitations
- Playwright `recordVideo` captures the source at **25 fps** (measured). The output is 30 fps CFR with duplicated frames, no interpolation. True 60 fps needs the skill's WGC capture, which requires FFmpeg with `gfxcapture` (not in the local 7.1 essentials build).
- If a separately authorized recording takes longer, revise the storyboard using genuine footage rather than speeding it up; final build rejects footage shorter than each scene requires. Total length may then exceed 44 s.
- The macOS frame and zooms are a deliberate choice for the pitch. The base skill recommends against a permanent browser frame, but the team asked for a Mac-style presentation. Zooms are functional only: the target is fully in frame and the zoom settles before the action.
