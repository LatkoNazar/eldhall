# Eldhall pitch video (44 s, 1920×1080)

Video for slide 7 of the deck (`deliverables/pitch`). The pipeline follows the repo skill `.agents/skills/eldhall-mvp-demo`: **Playwright** records the real UI with a live Eldhall pointer, and **Hyperframes 0.8.221 + GSAP** add the macOS window, transitions, zooms, highlight rings and captions. Inter is bundled locally from `@fontsource/inter` (OFL). There is no voice-over: captions only, so the speaker can talk over the video.

**Honesty rule:** frames inside the window come only from a real recording of the MVP. A missing recording is shown as a striped **PLACEHOLDER** panel with a «ЧЕРНЕТКА» badge, and `build.mjs --final` refuses to build with placeholders. The refund is labelled "simulated provider" throughout.

## Files
| Path | Purpose |
|---|---|
| `scenes/pitch.json` | storyboard: 8 scenes, durations, slots, estimated zoom/highlight areas (capture px 1600×900) |
| `scenes/geometry.json` | **generated by capture**: real element coordinates and times; overrides the estimates |
| `locales/uk.json` | all captions and titles |
| `styles.css`, `main.js` | Eldhall style, macOS frame, deterministic GSAP timeline |
| `scripts/build.mjs` | generates `index.html`, `scene-timing.json`, `assets/ledger.json` (SHA-256 of the footage), `exports/*.srt` |
| `scripts/capture.mjs` | real recording + backend state check through the API |
| `capture.config.json` | UI locators (regex) — edit here after WS2, no code changes |
| `assets/capture/<scene>.mp4` | **slots** for real footage (request, triage, policy, approve, execute, result, safety) |

## Final (after a confirmed E2E)
1. Start the MVP (API + frontend) and check the URL in `capture.config.json` (`appUrl`, `apiUrl`). The `/chat` and `/operator` pages must exist.
2. Check the locators in `capture.config.json` against the real UI (button names, labels).
3. Record and verify:
   ```bash
   OPERATOR_TOKEN=<token> node scripts/capture.mjs
   ```
   The script does a demo reset and two continuous sessions (chat + console): Olena → copilot reply → Inbox P1 case + signals → policy checklist → **«Погодити повернення»** (approved, no money moved) → separate **«Виконати погоджену дію»** (executed, `SIM-RF-…`) → confirmation in chat; Ivan (via the real chat API) → `within_refund_limit` denial + escalation. Then it checks through the API: Olena `resolved` + 1 refund + `executed`; Ivan `escalated` + `denied` + 0 refunds. If the state does not match, no slot is written (`capture/evidence.json`). In rules mode it warns that the captions must not claim LLM tool calls.
4. `node scripts/build.mjs --final` → `npx hyperframes check` → snapshot review:
   ```bash
   npx hyperframes snapshot --at 6,12,18,24,30,36 --no-end --output .hyperframes/review
   ```
5. Final render (~3–5 min at `delivery` quality):
   ```bash
   npx hyperframes render --fps 30 --quality delivery --workers 3 --output exports/eldhall-pitch-uk.mp4
   ```
6. QA: `ffprobe` (1920×1080, 30 fps, ~44 s), a full decode `ffmpeg -v error -i exports/eldhall-pitch-uk.mp4 -f null -`, one full watch-through, and a check that every caption matches `capture/evidence.json`.
7. Slide 7: PowerPoint › Insert › Video › `exports/eldhall-pitch-uk.mp4` (see `deliverables/pitch/README.md`).

## Known limitations
- Playwright `recordVideo` captures the source at **25 fps** (measured). The output is 30 fps CFR with duplicated frames, no interpolation. True 60 fps needs the skill's WGC capture, which requires FFmpeg with `gfxcapture` (not in the local 7.1 essentials build).
- If the real flow is longer than the storyboard (e.g. a slow LLM reply), `capture.mjs` lengthens the scene with a real hold instead of speeding up the footage. Total length may then exceed 44 s.
- The macOS frame and zooms are a deliberate choice for the pitch. The base skill recommends against a permanent browser frame, but the team asked for a Mac-style presentation. Zooms are functional only: the target is fully in frame and the zoom settles before the action.
