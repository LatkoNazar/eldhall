# Демо проєкту

Тут зберігаються **версійовані вихідні проєкти та затверджені відео**. Їх можна
клонувати разом із репозиторієм і редагувати локально.

- [`reference/youtube/`](reference/youtube/README.md) — готовий приклад пайплайна
  Playwright / WGC → Hyperframes, з перевіреним MP4. Це демонстрація YouTube,
  **не відео нашого MVP**.
- Нові записи MVP клади в `demos/mvp/<назва-сценарію>/` або інший зрозумілий slug
  під `demos/`. Записуй фактично реалізований інтерфейс поточної гілки.
- Інструкція для агента: [`$eldhall-mvp-demo`](../.agents/skills/eldhall-mvp-demo/SKILL.md).

## Отримати медіафайли

Бінарні відео, аудіо та зображення під `demos/` використовують Git LFS за правилами
кореневого `.gitattributes`. Після клонування:

```powershell
git lfs install --local
git lfs pull
cd demos/reference/youtube
npm ci
npm run verify
npm run build
npm run dev -- --background
```

`git lfs pull` має завантажити справжні файли, а не залишити текстові LFS pointers.
`npm run verify` перевіряє це та контрольні суми прикладу. Потрібні Node24.x і
FFmpeg / FFprobe у PATH; конкретні команди перевірки й рендера є в README прикладу.

## Що зберігати в Git

Для кожного демо тримай разом:

```text
<demo>/
  README.md                 # сценарій, запуск, перевірка, рендер, походження
  package.json + lockfile    # зафіксовані інструменти
  scripts/, scenes/, locales/, styles.css, main.js, index.html
  assets/video/             # остаточні джерела сцен, LFS
  assets/audio/             # озвучка LFS, текстові SRT звичайним Git
  assets/cursor/            # SVG + hotspots
  exports/                  # затверджені MP4 (LFS) та SRT
  qa/                       # звіт, SHA-256 і відібрані докази перевірки
```

`.gitignore` у цій папці виключає залежності, тимчасові рендери, кадри, кеш,
профілі браузера, auth state та raw-записи. Raw можна додавати лише свідомо,
якщо вони потрібні для відтворення й не містять приватних даних; це не типовий
результат. Профілі та секрети не додавай навіть тоді. Для погодженого raw-джерела
обери окрему явно названу папку й перевір LFS до додавання.

Новий рендер спочатку потрапляє в ігноровану `renders/`. Після незалежної
перевірки скопіюй прийнятий результат в `exports/`, збережи його SHA-256 та звіт.
Вихідні файли і фінальні медіа готуються для звичайного Git-review; запис демо
сам собою не означає автоматичного commit або push. Не додавай великі бінарні
файли до звичайної Git-історії в обхід LFS.

Стара `eldhall-demo/` залишається локальним експериментом. Нові проєкти в `demos/`
не повинні читати з неї файли чи залежати від абсолютних шляхів автора.
